# AI Usage

## Tools and models

I used GitHub Copilot CLI (agent) to build the code, tests, and docs under my direction. The model was the CLI default or my selection; its exact version was not recorded. I also used a separate chat assistant (Claude, via claude.ai) for planning, writing task prompts, and triaging review findings; its exact model version was not recorded. The recorded engineering tools include Git, npm/Vitest/ESLint/TypeScript, SwiftPM/Xcode, curl, and Mailpit.

## Plan / spec

The work followed [`docs/PRD.md`](docs/PRD.md), [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md), [`docs/RULES.md`](docs/RULES.md), [`docs/DESIGN.md`](docs/DESIGN.md), [`docs/TASKS.md`](docs/TASKS.md), and [`docs/MEMORY.md`](docs/MEMORY.md). The T0-T15 sequence split the PoC into ordered vertical slices, with one task and one commit at a time; the history also shows separate review-fix and documentation commits. Prompts were handled one task at a time rather than combining unrelated implementation changes.

## Key prompts / moments

1. **T0 project skeleton** (`2277549`, `Set up project skeleton`). **Prompt excerpt:** “Do task T0 only. Do not implement any business logic yet.” The requested report-back listed files created, commands and their real results, assumptions or deviations, and anything unsure. **Produced:** the folder and backend scaffold, health endpoint, test, Docker setup, and README stub. **What I checked or decided:** the T0 commit and its requested install/test/lint sequence; the repository does not preserve the exact terminal output from that run. **Why it mattered:** it set up the project without starting business logic.
2. **T4 enquiry feature** (`d69948d`, `Add enquiry endpoint and email adapters`). **Prompt excerpt:** “Do task T4 only: the enquiry feature with an EmailSender port, console and SMTP adapters, validation, rate limiting and sanitising, with tests.” The prompt listed `@fastify/rate-limit`, `nodemailer`, and `@types/nodemailer` as approved additions. **Produced:** the email port and adapters, enquiry handling, validation, rate limiting, sanitising, and tests. **What I checked or decided:** I later recorded a successful Mailpit delivery in `docs/ARCHITECTURE.md`; I did not rerun that live flow during this documentation pass. **Why it mattered:** the email provider can be changed behind the port, and the enquiry path has tested input and delivery boundaries.
3. **Clean-state backend startup check** (`4c97cb3`, `Make backend start work without an env file`; `docs/MEMORY.md`, 2026-11-05 03:10). **Prompt excerpt:** “verify from a clean state ... cp .env.example .env and run npm start”. **Produced:** the check exposed that `npm start` uses process environment and does not load `.env`; startup paths were separated so `start:local` loads the file. **What I checked or decided:** a clean copy with and without configuration, the health response, and the clear missing-variable diagnostic. **Why it mattered:** local setup and container/CI startup now have explicit, distinct environment behavior.
4. **Read-only review** (`2590ebe`, `Add review and security audit reports`). **Prompt excerpt:** “This is a READ-ONLY review ... Do NOT change any source, test, config or doc file”. **Produced:** `docs/reviews/REVIEW.md` with R1-R5 and `docs/reviews/SECURITY.md` with S1-S3. **What I checked or decided:** I triaged findings separately; one review pass still edited CI, and the R1 fix was later isolated in `4528d9b`. **Why it mattered:** the reports made risks and follow-up choices explicit, while also showing why a read-only pass needs a worktree check.
