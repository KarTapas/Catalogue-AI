## Key design decisions

| Decision | Alternatives | Why | Trade-off |
|---|---|---|---|
| Require a backend between iOS and catalogue/email providers (brief constraint 2). Product metadata and enquiries use it; product images are the accepted direct-network exception in R2/S1. | Direct Fake Store requests from iOS (prohibited by `docs/PRD.md`, Constraints). | I kept metadata and enquiry traffic behind the backend because the PRD requires that boundary and the backend owns the provider integrations; product images are the accepted R2/S1 exception (`docs/PRD.md`, Constraints; `docs/ARCHITECTURE.md`, System). | There is another service to configure and run. Images still load from the URL in backend-provided data. |
| Use Fastify for the backend HTTP server. | Express (named as the offered alternative in the brief). | I used Fastify as the server specified in the brief; I did not record a reason for this beyond the requirement; I would explain the trade-off in the interview. | Fastify and its plugin lifecycle are part of the server and test setup. |
| Put product and email I/O behind `ProductSource` and `EmailSender` ports. | Alternatives not recorded. | I put provider I/O behind ports because the PRD says the product source and email provider are expected to change (`docs/PRD.md`, Goal; `docs/ARCHITECTURE.md`, Extension points). | Adds interfaces and composition wiring in `backend/src/server.ts`. |
| Keep `CatalogueDomain` and `CatalogueData` as separate Swift package targets. | Alternatives not recorded. | I separated the targets so SwiftPM enforces `CatalogueData` depending on `CatalogueDomain`, while Domain has no target dependencies (`docs/ARCHITECTURE.md`, Dependency rule). | Package and test structure has more targets to maintain. |
| Inject `HTTPTransport` instead of stubbing requests with `URLProtocol`. | `URLProtocol` interception instead of an injected transport (the alternative recorded for HTTP tests). | I injected the transport so API tests can use a deterministic fake without network access (`docs/ARCHITECTURE.md`, iOS Data layer). | The fake tests the API client boundary, not the real `URLSessionTransport`; a direct offline test of that transport remains a next step. |
| Define the app in XcodeGen YAML and commit the generated Xcode project. | Alternatives not recorded. | I did not record a reason for this beyond the requirement; I would explain the trade-off in the interview (`docs/MEMORY.md`, 2026-11-04 21:30 records the generated project and YAML source). | The generated project must be regenerated when its YAML source changes. |
| Configure the API base URL through xcconfig and `Info.plist`. | Alternatives not recorded. | I used build configuration for the API URL so Debug can use localhost and Release can remain unset until a real host exists (`docs/MEMORY.md`, 2026-11-04 21:30; `ios/CatalogueApp/Composition/AppConfig.swift`). | Release cannot start until a production API URL is supplied. |
| Permit insecure HTTP only for `localhost` in ATS. | Alternatives not recorded. | I limited the exception to localhost so the Simulator can reach the local backend without allowing arbitrary insecure loads (`docs/MEMORY.md`, 2026-11-04 21:30; `docs/reviews/SECURITY.md`, Security checks). | `localhost` does not refer to a backend on a physical device; production must use HTTPS. |
| Run search on explicit submit and use request IDs/cancellation for latest-submit-wins. | Alternatives not recorded. | I kept search on explicit submit because US3 says to tap the search button; request IDs keep an older response from replacing a newer submitted result (`docs/PRD.md`, US3; `docs/MEMORY.md`, 2026-11-04 22:50). | No live autocomplete; cancellation and request state add ViewModel logic. |
| Let the backend calculate the category top-three split and let iOS render it as returned. | Alternatives not recorded. | I kept the split in the backend because the API contract returns `topRated` and `others`, and the architecture says iOS preserves their order (`docs/ARCHITECTURE.md`, API contract and iOS patterns). | The client depends on the backend's ordering contract. |
| Validate on both client and server, counting string lengths as UTF-16 code units. | Alternatives not recorded. | I aligned the length rules after R3 showed JavaScript `.length` and Swift grapheme counts could disagree (`docs/reviews/REVIEW.md`, R3; `docs/MEMORY.md`, 2026-11-05 10:43). | Validation rules are duplicated and must stay synchronized. |
| Defend email headers at both the HTTP boundary and email service. | Alternatives not recorded. | I reject or strip header controls at the boundary and service, and escape user values in HTML email, as required by the documented security basics (`docs/ARCHITECTURE.md`, Security basics; `backend/src/services/enquiryService.ts`). | The two layers require tests and coordinated maintenance. |
| Use Mailpit for local SMTP. | A real email provider is a future option; the PRD expects the provider to change later. | I used Mailpit to inspect local email without production credentials; Compose supplies the SMTP service and web UI (`docs/ARCHITECTURE.md`, System; `docs/PRD.md`, Goal). | Mailpit does not verify authenticated TLS negotiation with a real provider. |
| Keep `npm start` environment-only and add `start:local` for `.env`. | Using Node's `--env-file=.env` for every `npm start` (recorded as an earlier approach in `docs/MEMORY.md`). | I kept container/CI startup independent of a local `.env`; the clean-state check led to a separate `start:local` path for developers (`docs/MEMORY.md`, 2026-11-05 02:23 and 03:10). | Developers use the explicit `start:local` command when they want `.env` loaded. |
| Keep read-only review and implementation fixes in separate passes. | Alternatives not recorded. | I followed the Reviewer and Security Auditor role guidance for separate review passes; the first review's CI edit is recorded as a process mistake (`docs/MEMORY.md`, 2026-11-05 11:15). | The first review pass accidentally edited CI; the process needs a worktree check to preserve read-only reviews. |
| Load images from the source URL included in product data (accepted R2/S1). | Proxy images through the backend with a host allow-list (review R2/S1). | I kept direct image loading for this PoC after accepting R2/S1; the mapper limits schemes to HTTP/HTTPS, but there is no host allow-list and a proxy adds SSRF risk (`docs/reviews/SECURITY.md`, S1). | The device still contacts the supplied host directly; no host allow-list or proxy is present. |
| Require TLS only when SMTP credentials are configured; use implicit TLS on port 465. | Alternatives not recorded. | I require TLS with credentials while preserving unauthenticated Mailpit SMTP; port 465 uses implicit TLS (`docs/MEMORY.md`, 2026-11-05 10:43; `docs/reviews/SECURITY.md`, S2). | Authenticated TLS has not been tested with a real provider. |
| Keep the Xcode app target in Swift 5 language mode. | Alternatives not recorded. | I kept Swift 5 mode to match the package's Swift tools 5.9 default (`docs/MEMORY.md`, 2026-11-04 21:30). | Strict Swift 6 concurrency checking remains future work. |
| Keep Search visible as a compact icon-only button inside the field row. | Alternatives not recorded. | I kept a visible Search action because US3 requires tapping the search button; the compact icon keeps that action while reducing vertical space (`docs/PRD.md`, US3; `docs/MEMORY.md`, 2026-11-05 12:31). | Preserve 44pt targets and explicit disabled state/semantics. |

## How the design supports growth beyond the PoC

| Change | Existing seam | What is not exercised |
|---|---|---|
| Swap the product source | Implement `ProductSource` in `backend/src/domain/ports.ts`, add an adapter beside `backend/src/adapters/fakeStoreProductSource.ts`, and compose it in `backend/src/server.ts`. | Only Fake Store is implemented; a second source was not tested. |
| Swap the email provider for AWS SES | Implement `EmailSender` in `backend/src/domain/ports.ts`; `ConsoleEmailSender` and `SmtpEmailSender` show the current adapters. | No SES adapter or AWS email service was exercised. |
| Replace the look and feel | Replace tokens and components under `ios/CatalogueApp/DesignSystem/`. | A second design system or a creative-team redesign was not exercised. |
| Deploy the stateless backend container to AWS | `backend/Dockerfile` builds a Node container; configuration is provided through the environment. | I ran `docker compose up --build` once on 2026-11-05; the backend started, app requests for categories, featured products, and category pages returned 200, and an app-submitted enquiry email appeared in Mailpit. No AWS deployment was made. |
| Add enquiry persistence | Add the backend `EnquiryRepository` port and adapter described in `docs/ARCHITECTURE.md`; the existing iOS port with that name is for remote submission, not persistence. | There is no backend persistence port or database adapter today; this growth path was not exercised. |

## What I would do next with another day

The first three priorities are fixed here; the remaining items are ordered by risk.

1. Persist enquiries so a failed email does not lose the enquiry.
2. Run CI on GitHub and move the iOS jobs to a per-job repository-root working directory.
3. Add a backend image proxy with an allow-list and a failure UI for images.
4. Verify authenticated SMTP TLS against a real provider; current tests cover transport options, not a provider handshake.
5. Add security headers and define proxy-aware rate limiting for the deployment topology.
6. Pin container images by digest and GitHub Actions by commit SHA.
7. Add an offline test for the production `URLSessionTransport`.
8. Run VoiceOver and Dynamic Type checks beyond the captured screenshots.
9. Replace `CATALOGUE_DISABLE_AUTOMATIC_HOME_LOAD` with an injected `autoLoad` flag.
10. Enable and resolve strict Swift 6 concurrency diagnostics.
11. Add SwiftLint.
12. Add pagination if product size or performance requires it.
